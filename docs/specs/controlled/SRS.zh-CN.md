# 软件需求规格说明书 — `sanguo`

包 `sanguo` 是 `lethebar` 的三国世界。本文件说明这个包必须做什么，不说明引擎如何实现回合、存档与渲染——那些属于引擎自己的规格。

需求使用固定 ID。后续版本可以新增需求，但不得用同一个 ID 指代另一种行为。

## 1. 范围

玩家开始一局，每回合花掉一个行动，看到四项资源随之变动。二十四回合后结束；若军队喂不起、养不住或不再被信任，会更早结束。

范围内：包的数据、它声明的接口、它的文本、两张素材，以及存档所依赖的身份。

范围外：引擎、菜单、存档格式，以及把包变成运行中游戏的规则。

## 2. 术语

| 术语 | 含义 |
|---|---|
| 包（Pack） | 引擎安装的单位：一个 `manifest.json`、`data/`、`assets/` |
| 局（Run） | 一次游玩，从入口节点到某个结局 |
| 回合（Turn） | 花掉一个行动，世界时钟走一格 |
| 段位（Rank） | 某一回合显示的头衔 |
| 资源（Resource） | 局中携带的数值：`grain`、`troops`、`coin`、`standing` |

## 3. 功能需求

**REQ-001 — 包自我标识。**
`packs/sanguo/manifest.json` 声明 `id` `sanguo`、`version`（当前 `1.0.0`）、`specVersion` `2.0.0`、`kind` `bundle`、`protocol` `turn_based@1`、`entry` `n1`。`id` 永不改变：存档键是 `save:<id>:<slot>`。

**REQ-002 — 一局二十四回合。**
`data/phases.json` 声明 `turns` 为 `24`。任何配置都不会让一局更短或更长。

**REQ-003 — 五个段位落在五个回合。**
第 1 回合 `校尉`，第 6 回合 `都尉`，第 11 回合 `偏将军`，第 16 回合 `将军`，第 21 回合 `大将军`。两个节点之间沿用前一段位的头衔。

**REQ-004 — 四项资源，各有初值与上下限。**
`grain` 初值 40，界于 0–100；`troops` 初值 30，界于 0–100；`coin` 初值 12，界于 0–60；`standing` 初值 1，界于 0–4，带五个标签，从 0 的 `众叛亲离` 到 4 的 `号令天下`。

**REQ-005 — 资源归零则一局结束。**
`grain`、`troops` 或 `standing` 降到 0 或以下，一局结束，并说明原因：粮草断绝、士卒溃散，或诸侯离心。`coin` 不是失败条件；它可以降到 0，一局继续。

**REQ-006 — 五个行动，各有代价与效果。**
`farm` 耗 1 金帛、得 10 粮草；`recruit` 耗 5 粮草、得 8 兵员；`drill` 耗 3 粮草、得 3 兵员与 1 声望；`envoys` 耗 2 金帛、得 1 声望；`patrol` 耗 2 兵员、得 4 粮草。先扣代价，再生效果。

**REQ-007 — 三条由声望驱动的规则在局中生效。**
第 12 回合起，每次推进加 1 粮草。声望不低于 2 时，`cao` 对 `shao` 的关系每次变动 -5。声望不低于 3 时，`liu` 对 `cao` 的关系变动 +5。

**REQ-008 — 三方势力，带初始关系。**
`shao` 对 `cao` 为 -20，`cao` 对 `shao` 为 -20，`liu` 对 `cao` 为 30。关系达到 60 及以上读作盟友，-60 及以下读作敌对。

**REQ-009 — 一局从节点 `n1` 开始。**
`data/nodes.json` 只有一个节点 `n1`，带开场文本，以及绑定到 `scene` 与 `audio` 两个槽位的两张素材。该节点不声明选项；玩家花掉一回合所用的是 REQ-006 的那些行动。

**REQ-010 — 叙事面是声明出来的，不是推断的。**
manifest 声明故事以第三人称、密集地阅读，点名三个角色——曹操（魏）、袁绍（盟主）、吕布（骁将）——并在第 1、6、11、16、21 回合给出五段弧光：`初平元年 · 起兵`、`群雄并起`、`中原逐鹿`、`三分之势`、`天下归心`。

**REQ-011 — 包说明它给谁玩、要多久。**
`meta.audience` 为 `adults`，`meta.minutes` 为 30，`meta.pitch` 各有一句 `zh-CN` 与一句 `en`。

**REQ-012 — 包属于一个有名字的世界。**
`collection.id` 为 `three-kingdoms`，展示名为 `三国` 与 `Three Kingdoms`。世界标识不是包 id，也不随包改名。

**REQ-013 — 每一句可见中文都有对应的英文。**
`defaultLocale` 为 `zh-CN`，`locales` 列出 `en`。`data/i18n/en.json` 覆盖入口节点文本、五个行动名、五个段位、五个声望标签与三条失败原因。字体由引擎提供，包不带字体。

**REQ-014 — 本包写出的存档保持可读。**
`saveSchema` 为 `1`。包可以在该 schema 内加内容；不得改动 schema、`id` 或 `entry`，除非有新的决策记录与新的主版本。

**REQ-015 — 两张素材，连同槽位一起声明。**
`assets/scene.png` 是槽位 `scene` 的贴图；`assets/theme.wav` 是槽位 `audio` 的音频。两者都在 manifest 中声明，并位于 zip 内 manifest 所指的路径上。

## 4. 约束

**REQ-016 — 包是数据，不是代码。**
zip 里没有可执行的东西。引擎在读取任何内容之前先校验声明的大小、条目数与压缩比。

**REQ-017 — 包只用引擎已经提供的能力。**
`render.2d@1`、`text@1`、`ledger@1`、`rules@1`、`phases@1`、`menu@1`、`relations@1`。新增能力属于引擎改动，不属于包的改动。

**REQ-018 — 包在它声明的引擎上运行。**
`engine` 为 `>=4.7.0 <5.0.0`。确实需要更新的引擎时可以上调下界；不得把上界放到下个主版本之外。

**REQ-019 — 构建可复现。**
同一棵树两次构建产出相同字节的 zip，读者据此可用发布的 `sha256` 核对下载。

## 5. 非目标

- 回合结算、存档编码、渲染与菜单行为。
- 在游戏运行中安装包。
- 后续版本计划的卡牌层与战略层。

## 6. 验收

以上每条需求都由测试计划中一个或多个用例检查。没有用例的需求不算验收通过；没有引用需求的用例不执行。
